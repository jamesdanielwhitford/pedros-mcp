# Session 001 — 2026-07-16

## Status: in progress

## What this project is
Building a Claude-based ordering tool for Pedro's, so a customer can order and pay for a meal through Claude. Pedro's already has a mobile app that uses Payfast as its online acquirer, and menus are available via an existing API.

Clarified scope: this should not be a single customer-facing chat widget. The goal is for *any* Claude surface (claude.ai, Claude Desktop, Claude Code) to be able to place an order, which points to building a **remote MCP server** for Pedro's, registered as a Claude Connector, rather than a bespoke app per surface.

## What was done this session
- Researched feasibility using a combination of WebSearch/WebFetch and claude-in-chrome (the `better-research` skill's scripted path failed — missing Python deps `bs4`/`readability-lxml`/`markdownify`, and `pip install` is blocked by Homebrew's externally-managed-environment guard; did not force `--break-system-packages`, fell back to claude-in-chrome per the skill's documented fallback).
- Confirmed via Payfast's own docs (`developers.payfast.co.za/docs`) how integration works: Custom Integration (redirect to hosted payment page), Onsite Payments (Beta, in-page modal via JS + `/onsite/process` UUID), ITN webhook for payment confirmation (4 required verification checks: signature, source IP, amount match, live server validation), Recurring Billing/Tokenization for saved-card repeat charges, and PCI DSS Level 1 compliance (merchant never touches card data either way).
- Confirmed via Anthropic's docs how Claude tool use works (`tool_use` -> app executes -> `tool_result`) — Claude never executes real-world side effects itself, so a payment tool only ever *triggers* a Payfast checkout session, never handles a card number.
- Looked at Stripe/OpenAI/Meta's Agentic Commerce Protocol as an industry reference point — same principle (scoped, single-use payment token/session, agent never holds raw card).
- Confirmed Claude Connectors / remote MCP servers: a third party hosts their own MCP server, registers it as a connector, and it's then usable from every Claude client (claude.ai, Desktop, Code, mobile) via Anthropic's cloud infra connecting out to it. OAuth can be configured per-connector for user identity.

## Proposed architecture (from research, not yet built)
```
Claude (any surface) ── MCP ──> Pedro's MCP Server ──> Menu API (existing)
                                                    └──> Order backend ──> Payfast
```
MCP tools: `get_menu`/`search_menu`, `create_order`/`update_cart`, `checkout` (creates Payfast payment session — Custom Integration redirect or Onsite Payments modal), `get_order_status` (polled after ITN confirms).
