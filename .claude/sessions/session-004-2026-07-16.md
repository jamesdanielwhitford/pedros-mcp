## Decisions / reasoning
- The demo skips OAuth/identity (§7) entirely — it's a single guest checkout flow, not a real customer base, so there's no reason to build Connector auth just to prove the architecture works.
- Menu data is mocked/hardcoded for the demo rather than integrating Pedro's real menu API — not accessible, and not needed to prove the MCP tool surface, cart flow, checkout, and ITN confirmation loop actually work end-to-end.
- One Worker, two routes (`/mcp` via `routeAgentRequest()`, falling through to `/webhooks/payfast-itn`) rather than a separate service — confirmed as the standard Agents SDK composition pattern, no extra router library needed.
- Sandbox's single-notification ITN behavior (no retry) is called out explicitly because it's a real divergence from production that the held-open `checkout`/timeout logic (§4) needs to tolerate, not just a footnote.
