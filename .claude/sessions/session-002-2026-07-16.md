## What was done this session
Deepened the architecture research from session 001, targeting four specific areas rather than re-covering the same ground. Used `/better-research` (scripted requests/Playwright fetch → readability/markdownify) as the primary method, per user preference for grounded, real page text over a browsing agent's paraphrase.

1. **MCP Connector OAuth mechanics** (`research/mcp-oauth-mechanics.md`) — resolves the "how does the server know who's ordering" open question from session 001: without OAuth, Claude passes zero user identity to a connector's server (no user ID, no session token) — every order would be structurally anonymous. OAuth 2.1 + mandatory PKCE is the only mechanism; documented the full flow (401 → Protected Resource Metadata → authorization server discovery → client registration via CIMD/DCR/pre-registered creds → redirect → token exchange → Bearer token on every tool call), callback URLs per Claude surface, and token lifecycle (Anthropic-side encrypted storage/refresh, disconnection doesn't revoke at the IdP).

2. **Reference implementations** (`research/mcp-commerce-reference-implementations.md`) — found Stripe's own "MCP apps" monetization docs (Redirect vs. Instant Checkout, mapping directly onto Payfast's Custom vs. Onsite Payments) and a concrete open-source food-ordering agent (Temporal AI Agent's "Tony's Pizza Palace") that splits cart-building (native, local, non-payment tool) from checkout (MCP tools calling Stripe) — validates keeping Pedro's own `checkout` tool as the only one that ever touches Payfast.

3. **MCP server hosting/infra** (`research/mcp-hosting-infra.md`) — researched Cloudflare Workers' `McpAgent` (Durable-Object-backed stateful MCP server) + `workers-oauth-provider` as one concrete, well-documented hosting path, explicitly evaluated because it's tooling this workspace already has, not because Pedro's infrastructure is known. Found MCP's **elicitation** mechanism (URL mode) maps directly onto Payfast's redirect/Onsite checkout flow — the concrete mechanism for the `checkout` tool. **User flagged mid-session that this is researcher-side tooling bias, not a Pedro's decision** — corrected the file to caveat this explicitly rather than imply Cloudflare is the answer.

4. **Payfast Onsite Payments + ITN deep-dive** (`research/payfast-onsite-itn-details.md`) — attempted to re-fetch Payfast's docs directly (scripted fetch) to get past the earlier claude-in-chrome-only summary. Payfast's docs are a JS single-page app that resists both plain `requests` and headless Playwright (returns only a generic shell, not the full tabbed reference content) — this file honestly reports that outcome: confirms the existing summary via a second method, but doesn't add new field-level detail. Flagged that exact request/response shapes should be re-verified via claude-in-chrome or the official PayFast PHP SDK source before they become load-bearing for actual implementation code.
